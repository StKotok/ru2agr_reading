# Visual Design Review — 2026-06-16

Дизайн-ревизия приложения «Греческая читалка НЗ» — взгляд с точки
зрения пользовательского опыта и визуальной эстетики, не кода.

## Контекст

Приложение — читалка Нового Завета с прогрессивным греческим слоем:
русский Синодальный текст, в который подмешиваются греческие буквы и слова
по мере изучения. Пользователь — человек, изучающий библейский греческий
в спокойном темпе. Ключевое слово — **спокойная читалка**.

## Что работает хорошо

- **Цветовая палитра.** Тёплый бежевый фон (`#efeee9`) создаёт бумажное,
  не-цифровое ощущение. Синий для букв и терракотовый для слов —
  интуитивно понятное разделение. Тёмная тема сохраняет тепло.
- **Gentium Plus.** Академический греческий шрифт с правильными диакритиками.
  Хорошая читаемость на экране.
- **Bottom sheet / popover.** Мобайл получает нижний шторку, десктоп —
  всплывающую карточку. Правильный адаптивный паттерн.
- **Сетка букв на экране прогресса.** `aspect-ratio: 1`, ровные клетки —
  визуально приятно, напоминает алфавитную таблицу.
- **Чип режима.** `α35% · λέγω 12` — компактный индикатор состояния,
  информативный при минимальном размере.
- **Анимации.** Естественные: toast снизу, bottom sheet вверх, popover
  с небольшим смещением. Нет перегруженности motion.

## Проблемы и рекомендации

### 1. Длина строки на десктопе — «бесконечная строка»

**Что сейчас:** `.scripture-text` имеет `max-width: 65ch` на мобильных,
но на десктопе (≥900px) `max-width: none` — текст растягивается на всю
ширину контейнера. При боковой панели 200–240px и инспекторе 260–360px
остаётся ~400–700px на текст, но на широких экранах (1440px+) строки
уходят за 100 символов.

**Почему плохо:** Оптимальная длина строки для комфортного чтения —
45–75 символов. При 100+ символах глаз теряет строку при переносе на
следующую.

**Рекомендация:** Вернуть `max-width: 70ch` для десктопа, центрировать
текст внутри screen-container:
```css
@media (min-width: 900px) {
  .scripture-text {
    max-width: 70ch;
    margin: 0 auto;
  }
}
```

### 2. Заголовки глав — «невидимые ориентиры»

**Что сейчас:** `<h2>` с `color: var(--muted)`, `font-size: 1.25rem`,
`position: sticky; top: 0; background: var(--surface)`. Заголовок серый
на бежевом — визуально отступает на задний план.

**Почему плохо:** Заголовок главы — главный навигационный ориентир
в читалке. Пользователь скроллит и ищет «где я сейчас». Приглушённый
серый заголовок не помогает.

**Рекомендация:** Использовать `color: var(--text)` с полужирным
начертанием. Добавить визуальный индикатор «прилипания» — когда
заголовок зафиксирован после скролла, показать `border-bottom: 1px solid
var(--border)`:
```css
.scripture-text h2 {
  color: var(--text);
  font-weight: 600;
  border-bottom: 1px solid transparent;
  transition: border-color 0.2s;
}
/* Прилипание определяется JS — добавить класс .is-stuck */
.scripture-text h2.is-stuck {
  border-bottom-color: var(--border);
}
```

### 3. Номера стихов — «исчезающий ориентир»

**Что сейчас:** `<sup>` с `font-size: 0.7em` и `color: var(--muted)`.
На мобильном это ~8–9px — практически нечитаемо.

**Почему плохо:** Номер стиха — навигационный якорь внутри главы.
Пользователь хочет найти «стих 14» — крошечный серый номер на серо-бежевом
фоне требует напряжения глаз.

**Рекомендация:** Увеличить до `0.75em`, использовать более тёмный
оттенок:
```css
.scripture-text sup {
  font-size: 0.75em;
  color: var(--muted);
  opacity: 0.8;
  font-weight: 600;
}
```

### 4. Карточка слова — «перегруженный диалог»

**Что сейчас:** `renderWordCard()` строит до 9 секций: форма, грамматика,
транслитерация, значение в стихе, другие значения, лемма, статус,
определение, происхождение. На мобильном экране это ~3–4 прокрутки.

**Почему плохо:** В учебном контексте пользователь нажимает на слово,
чтобы быстро узнать «что это значит». Вместо этого он получает
энциклопедическую статью. Когнитивная нагрузка превышает пользу для
начинающего.

**Рекомендация:** Двухуровневая карточка:
- **Уровень 1 (быстрый взгляд):** форма, транслитерация, значение
  в этом стихе, частотность. Это помещается на одном экране.
- **Уровень 2 (детали):** грамматика, лемма, определение, происхождение,
  другие значения — по кнопке «Подробнее».

Текущий механизм скрытия секций через шестерёнку — хороший, но
недостаточный: пользователь должен настроить карточку до того, как
увидит контент. Лучше показывать минимум по умолчанию и давать
развернуть.

### 5. Клетки «закрытых» букв — «сломанный, а не запертый»

**Что сейчас:** `.letter-cell.letter-locked` имеет `color: var(--muted)`
и `opacity: 0.4`. Визуально клетка выглядит «сломанной» или «ошибочной»,
а не «ещё не открытой».

**Почему плохо:** Эмоциональный дизайн. Пользователь видит тусклую,
полупрозрачную клетку — это сигнал «тебе сюда нельзя», а не «ты
откроешь это позже». Для учебного приложения это демотивирует.

**Рекомендация:** Заменить прозрачность на более тёплое «запертое»
состояние:
```css
.letter-cell.letter-locked {
  color: var(--muted);
  opacity: 0.5;
  background: var(--surface-card);
  border-style: dashed;
  cursor: not-allowed;
}
```

Пунктирная рамка + чуть более тёмный фон читаются как «заперто, но
доступно позже», а не как «сломано».

### 6. Позиция тоста на десктопе

**Что сейчас:** `.toast { position: fixed; bottom: 80px; }` — рассчитано
на мобильный (над нижней навигацией). На десктопе тост висит в 80px
от низа экрана — оторван от контента.

**Рекомендация:** Адаптивное позиционирование:
```css
@media (min-width: 900px) {
  .toast {
    bottom: 24px;
    left: auto;
    right: 24px;
    transform: none;
    max-width: 360px;
  }
}
```

### 7. Кнопка «глаз» (plain view) — невидимый toggle

**Что сейчас:** Кнопка с эмодзи 👁, `font-size: 0.8125rem`, на верхней
панели среди других мелких кнопок. Единственный индикатор активного
состояния — `background: var(--selection)`.

**Почему плохо:** Plain view — глобальный режим, который скрывает ВЕСЬ
греческий слой. Пользователь может случайно нажать и не понять, почему
исчез греческий. Визуальная обратная связь минимальна.

**Рекомендация:** Более заметный активный стиль:
```css
.top-bar-btn[aria-pressed="true"] {
  background: var(--primary);
  color: var(--on-primary);
  border-color: var(--primary);
}
```
(Сейчас используется inline style — лучше вынести в CSS-класс.)

### 8. Чип режима — «главный контрол слишком мал»

**Что сейчас:** `.mode-widget-chip` — `font-size: 0.8125rem`,
`border-radius: 14px`, `padding: 4px 12px`. Это главный (и единственный)
индикатор текущего режима чтения и вход в настройки слоя.

**Почему плохо:** Размер чипа конкурирует с кнопкой книги и кнопкой
«глаз» — все три одинакового визуального веса. Но чип — самый важный
контрол на экране чтения.

**Рекомендация:** Незначительно увеличить визуальный вес:
```css
.mode-widget-chip {
  font-size: 0.875rem;
  padding: 6px 14px;
  min-height: 36px;
}
```

### 9. Отсутствие перехода при смене режима чтения

**Что сейчас:** При изменении настроек (слайдер, тумблер слов, тема)
текст перерендеривается мгновенно — старый текст исчезает, новый
появляется в том же кадре.

**Почему плохо:** Резкая смена контента дезориентирует. Пользователь
теряет позицию на странице — «где я только что читал?»

**Рекомендация:** Добавить краткий fade-переход (150–200ms) на
контейнер текста при перерендере:
```css
.scripture-text.is-transitioning {
  opacity: 0.5;
  transition: opacity 0.15s ease;
}
```
JS: установить класс перед перерендером, убрать после.

### 10. Скелетон — «прямоугольники, а не контент»

**Что сейчас:** Три серых полосы разной ширины с pulse-анимацией.
Функционально, но не передаёт структуру будущего контента.

**Рекомендация:** Показывать скелетон, повторяющий структуру текста:
несколько «строк» разной длины + место для заголовка главы. Это
занимает столько же места, но точнее передаёт ожидание:
```css
.skeleton-verse {
  height: 1em;
  background: var(--border);
  border-radius: 3px;
  margin-bottom: 0.5em;
  animation: skeleton-pulse 1.5s ease-in-out infinite;
}
.skeleton-verse:last-child { width: 45%; }
```

### 11. Словарная строка на мобильном — «слишком плотно»

**Что сейчас:** `.dict-row` использует 4-колоночную сетку на мобильном
(rank | lemma | freq | check) + второй ряд (translit | badge).
При ширине экрана 360px на колонку lemma приходится ~150px — для
греческого текста этого достаточно, но визуально строка очень плотная.

**Рекомендация:** На мобильных немного увеличить вертикальные отступы:
```css
.dict-row {
  padding: 8px 10px;
  min-height: 48px;
}
```

### 12. Состояния-empty: «текст на карточке»

**Что сейчас:** Экран ошибки и оффлайн-состояния — это `<div
class="card error-state">` с текстом и кнопкой повтора.

**Рекомендация:** Добавить иконку (например, 📡 для оффлайна, ⚠️ для
ошибки) и немного визуального пространства:
```css
.error-state {
  display: flex;
  flex-direction: column;
  align-items: center;
  gap: 12px;
}
.error-state::before {
  content: '📡';
  font-size: 2rem;
  opacity: 0.6;
}
```

## Что сознательно НЕ меняем

- **Цветовую палитру.** Токены отрефакторены в предыдущей итерации,
  палитра сбалансирована.
- **Gentium Plus.** Замена на другой греческий шрифт не требуется.
- **Расположение навигации.** Нижняя панель на мобильном и боковая на
  десктопе — проверенный паттерн.
- **Bottom sheet / popover.** Адаптивный паттерн работает корректно.
- **Анимации.** Текущий набор motion — адекватный, не требует изменений.
