# Источник данных: SBLGNT.tsv

Единственный исходный файл пайплайна `npm run build:data`
(`scripts/convert-alignments.js`).

## Происхождение

- **Репозиторий:** <https://github.com/Clear-Bible/Alignments>
- **Путь:** `data/sources/SBLGNT.tsv`
- **Ревизия:** коммит `6473aa4` («publish WLCM-AVD, RUSSYN», 2024-09-27)
- **Содержимое:** токены греческого Нового Завета (SBLGNT) с леммами,
  морфологическими кодами и номерами Стронга; колонки
  `id, altId, text, strongs, gloss, gloss2, lemma, pos, morph`,
  идентификаторы вида `nBBCCCVVVWWW`.

## Почему здесь нет файлов выравнивания Clear-Bible

Ранее рядом лежали `SBLGNT-RUSSYN-manual.json` и `nt_RUSSYN.tsv` (ручное
выравнивание SBLGNT ↔ Синодальный). Эта пара файлов — даже взятая из одного
коммита upstream-репозитория — внутренне рассогласована: target-ID записей
ссылаются на другую (неопубликованную) токенизацию RUSSYN. Проверяемое
доказательство — Мф 1:1: запись с греческим токеном `n40001001004` (χριστοῦ)
указывает на токен «Давидова», а запись с `n40001001005` (υἱοῦ) — на запятую;
официальный ридер (`bible_alignments/burrito/alignments.py`) резолвит ID тем
же прямым lookup'ом. При таком декодировании ~54% пар, затрагивающих словарные
леммы, не соответствовали тексту.

Поэтому выравнивание строится детерминированно из этого файла и лексикона
проекта: русское слово, совпавшее с `ruMatches`-регуляркой лексемы
(`assets/data/lexicon/core.json`), сопоставляется очередному греческому токену
с тем же номером Стронга. Подробности и корпусные инварианты — в
`scripts/convert-alignments.js`.
