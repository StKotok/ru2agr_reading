# ALIGNMENT — план «с нуля», история и шпаргалка

> **Что это.** Единый документ про греко-английское пословное выравнивание: (1) чистый план
> «как сделать это заново», (2) история того, как это было сделано на самом деле (с найденными
> багами), (3) переиспользуемые выводы — шпаргалка для выравнивания **других переводов и языков**.
> Место в пайплайне — [PIPELINE.md §6](PIPELINE.md). Гейт-политика продукта — [PROJECT.md §5](PROJECT.md).
>
> Принцип, на котором стоит весь документ: **100% точность важнее % покрытия.**

## 1. Задача и почему она трудная

Сопоставить **глоссы** (привязаны к греческим токенам, в греческом порядке слов) со **словами
свободного перевода** (английский BSB, английский порядок слов). Это «подстрочник ↔ перевод», а не
«текст ↔ текст». Трудности:
- **Разный порядок слов** (греч. SOV vs англ. SVO): «to him said» ↔ «said to him».
- **Разный лексический выбор**: глосса `book` ↔ BSB `record`.
- **Лишние слова в переводе**: артикли, «this is», «the record of».
- **Нет 1:1**: один греческий токен → 0, 1 или несколько английских слов; и наоборот.
- **Многозначность**: лемма имеет набор глосс; какая из них — в этом стихе?

Соглашение об именах источников (`docs/source-data/CATALOG.md`): `glossEn` — Berean/PD (несёт
предлоги/артикли в скобках, `"[The] book"`), `english` — Cherith/CC-BY (чистая форма, `"book"`).
Не переименовывать по виду строки: скобки — не доказательство происхождения.

## 2. Принципы (accuracy-first)

**2.1. Три РАЗНЫХ понятия «правильности» — не смешивать.** Машина гарантирует только (a) и (b):

| Уровень | Что | Кто гарантирует |
|---|---|---|
| (a) механическая валидность span | в границах, непустой, есть буквы, без overlap | verify (span-checks) |
| (b) формальное соответствие span↔глосса | `slice` соответствует глоссе ПО МЕТОДУ | verify accuracy-инвариант |
| (c) семантическая правильность | этот токен действительно переведён этим словом | только ручной аудит |

«Accuracy hard-gate» = уровень (b). Он НЕ доказывает (c). Пример: `phrase` даёт `γένεσις` → span
`"of the genealogy"` — формально совпадает с глоссой `"of [the] genealogy"`, инвариант молчит, хотя
артикль/предлог не отдельные греческие слова. Семантику ловит только аудит (фаза 4) и тиринг.

**2.2. Гейт = точность + полное разбиение, НЕ покрытие.** Coverage% — advisory (без порога).

**2.3. Единственный кандидат = гарантия от угадывания.** Любой авто-проход создаёт пару ТОЛЬКО при
единственном несклеймленном слове-кандидате. Это уже встроено и НЕ ослабляется.

**2.4. Тиринг методов** (источник истины — `method`, не `q`):

| Тир | Методы | `q` | Условие |
|---|---|---|---|
| `proven` | gloss-exact, bracket-optional, phrase, alt-gloss-exact/bracket/phrase, lexicon-gloss-exact | `a` | формальное совпадение + единственный кандидат |
| `fuzzy` | fuzzy | `f` | fuzzy-совпадение + единственный кандидат; 100% аудит |
| `manual` | manual | `a` | человек; границы + `tokenId∈ref` + `slice==expectedText`; 100% аудит |
| `proposal` | positional-equal-count | — | **OFF по умолчанию**; в релиз не идёт без аудита |

`lexicon-gloss-exact` формально проверяем, но семантически самый слабый → **audit-required** + есть
corroboration-guard (см. 4.2 фаза 2).

**2.5. Честная партиция.** Каждый `fw=false` токен — ровно в одной категории:

| Категория | Кто ставит | `aligned`? |
|---|---|---|
| `aligned` (пара) | алгоритм/человек | да |
| `manual-exclusion` | человек, рукописный `reason` | нет |
| `no-bsb-verse` | авто: нет BSB-стиха для ref | нет |
| `no-gloss` | авто: обе глоссы пусты | нет |
| `auto-deferred` | авто-**backlog** (`no-matching-word`/`ambiguous`/`already-claimed`) | нет |

`auto-deferred` — техдолг «алгоритм не разрешил», **никогда не выдаётся за ручную курацию**.
`resolved = aligned ∪ все исключения`; покрывает остаток по построению → осмысленный гейт =
корректность разбиения + точность, а не «resolved==100%».

## 3. Контракты данных

**Alignment-книга** (`alignment-book-v3`): `pairsByRef` (пары со `span/tokenId/lexemeId/q/method`),
`warningsByRef` (диагностика проходов), `exclusionsByRef` (авторитетный слой разрешения: по записи
на каждый не-выровненный `fw=false` токен — `{tokenId, lexemeId, kind, reason, candidateCount?}`).

**Реестры** (`scripts/lib/align-normalize.mjs`): `ALIGN_METHODS` (закрытый перечень методов →
`{tier, q}`; неизвестный метод валит verify), `RESOLUTION_KINDS`, `AUTO_DEFER_REASONS`.

**`manual-alignments.json`** = `{ normalizationVersion, entries[] }`. Запись:
- пара: `{ ref, tokenId, method:"manual", wordIndex | wordIndexes[], expectedText }` — build
  компилирует span из `words[]` и сверяет `slice===expectedText` (куратор НЕ вводит сырые офсеты);
- исключение: `{ ref, tokenId, method:"manual-exclusion", reason }` (без span, без q).

⚠️ Ручные span'ы привязаны к `normalizationVersion`: при бампе — ревалидировать (verify Check 15c
сверяет версию файла с текущей и валит при рассинхроне).

## 4. Чистый план «сделать заново» (последовательно)

Порядок обязателен: каждая фаза опирается на предыдущую.

### Фаза 0 — починить фундамент ТЕКСТА (до любого выравнивания)
Span'ы и кандидаты строятся по `verse.text` + `words[]`. Пока текст склеен или неверно
токенизирован — выравнивание мусорное. Поэтому СНАЧАЛА:
1. **Бамп `NORMALIZATION_VERSION`** (любая правка текста меняет offsets всех eng-паков).
2. **Фикс сборки текста стиха**: вставлять пробел между фрагментами с word-символами на границе
   (терялся на месте `{noteId}`/между poem-строками → `overcomeit`, `poor;His`, `276of`). Единые
   константы sticky/opening-пунктуации.
3. **Токенизация**: `WORD_PATTERN = /[\p{L}\p{N}'’]+/gu` (включить curly `’`, иначе `God’s`
   рвётся → 394 стиха). Единый источник паттерна.
4. **Интеграционные тесты** (снапшоты битых стихов + comprehensive sweep на склейки + проверка `’`).
5. **Полная регенерация** `build:data` (текст → offsets → span'ы).

### Фаза 1 — сделать точность hard-gate
1. **Общий модуль нормализации** + `ALIGN_METHODS` (build и verify импортируют из одного места —
   иначе инвариант даёт ложные срабатывания).
2. **Golden-фикстуры** `checkPairAccuracy(slice, gloss, method)` (юнит-тест на ХАРДКОДЕ — ловит
   регрессию логики независимо от данных; иначе verify тавтологичен build'у).
3. **Accuracy-инвариант в verify**: для каждой пары — соответствие slice↔глосса по методу; `q ==
   ALIGN_METHODS[method].q`; запрет proposal-тира; **структурная проверка единственного кандидата**
   для proven (ровно 1 несклеймленное слово той же нормал-формы / ровно 1 непересекающееся окно);
   неизвестный метод → error.
4. **Coverage → warn** (подтвердить, что это advisory, exit-код от `errors`).
5. **Проверка `fw`/no-gloss**: `fw=false` без обеих глосс → должны быть покрыты `no-gloss` (иначе
   вечный unresolved); эвристика на ошибочный `fw=true`.
6. **Консистентность агрегатов** build-report (суммы per-book == тоталы).

### Фаза 2 — поднять покрытие БЕЗ потери точности
Все проходы — единственный кандидат, overlap-guard перед claim, `q="a"`. Порядок: Berean (1-3) →
Cherith → лексикон. «Ничья» (оба матчат одно слово) → выигрывает ранний (Berean), поздний пропускает.
1. **Berean**: exact (`gloss-exact`) → bracket-optional → phrase 2-4 contiguous.
2. **Cherith (`alt-gloss-*`)** — ГЛАВНЫЙ безопасный резерв: 50% токенов имеют `glossCherith ≠
   glossBerean` (Berean `"of God"` несёт предлог; Cherith `"God"` матчит одно слово). Пропускать,
   если Cherith пуст или после нормализации == Berean.
3. **`lexicon-gloss-exact`**: перебрать одно-словные глоссы лексемы (дедуп против уже проверенных
   token-level глосс). **Corroboration-guard (accuracy-first):** альтернативная лексемная глосса НЕ
   клеймит слово, которое является ПРЯМОЙ глоссой другого ещё-невыровненного токена стиха — лучше
   отложить, чем дать слабую пару.
4. **`positional-equal-count`** — proposal, **OFF** (инвариант не ловит позиционный мис-пэйринг).

### Фаза 3 — честная партиция + курация
1. **Build авто-классифицирует** каждый не-выровненный `fw=false` токен в `exclusionsByRef`
   (`no-bsb-verse` / `no-gloss` / `auto-deferred` с под-причиной). `manual-alignments.json` хранит
   ТОЛЬКО человеческие записи. **Никогда не генерировать псевдо-`manual-exclusion` скриптом.**
2. **Partition hard-gate** в verify: каждый токен ровно в одной категории; сверка счётчиков с report.
3. **`topUnalignedLexemes`** из auto-deferred (с `candidateCount`) — рабочий список куратора.
4. **Инструмент куратора** (`curate-align.mjs`): печатает текст с `[i]`-индексами слов + кандидаты.
5. **Курация**: для топ-лемм добавлять `manual`-пары (wordIndex/expectedText) или
   `manual-exclusion` с реальной причиной. Итерация → снижение backlog.

### Фаза 4 — финальный гейт + аудит
1. `build:data → verify:data` (0 errors) → `npm test` → `npm run build`.
2. **Детерминированный аудит (уровень c)**: `audit-align.mjs` (seed) — выборка по proven-методам +
   100% fuzzy/manual; человек смотрит семантику; результат фиксируется. Особое внимание —
   `lexicon-gloss-exact` (слабейший) и `already-claimed` (мис-пэйринг? — `audit-claimed.mjs`).
3. **Синхронизация документации** под фактическую модель.

## 5. История (как это было сделано на самом деле)

| Этап | Что произошло | Урок |
|---|---|---|
| **v1 алгоритм** | exact→bracket→phrase→fuzzy; coverage 53.5%; гейт «90% покрытия» | покрытие как гейт — неверная цель для подстрочника |
| **Completion-план** | ревью (verify, не trust): нашёл порчу BSB-текста (склейки в 142+ стихах) и **неиспользуемый `glossCherith`** (50% токенов) как главный резерв; переформулировал accuracy-first | чинить текст ДО выравнивания; искать неиспользуемый сигнал |
| **Имплементация** | coverage 53.5% → **81.8%** (Cherith + лексикон проходы); accuracy-инвариант, golden-тесты, тиринг методов | большой выигрыш от Cherith; инвариант — архитектурно верно |
| **❗ Подмена** | `resolved==100%` достигнут скриптом `bulk-curate.mjs`, пометившим **13 132** токена как `manual-exclusion` с шаблонными причинами (0 ручных пар) | автоподавление хвоста ≠ курация; нечестная модель |
| **Fixup F0–F4** | заменил фейк на честный `auto-deferred` (derived в build) + partition hard-gate; починил `audit-align` (аудировал 0 из-за `Object.entries` по Map); усилил manual-валидацию; `findStripFields` рекурсия в массивы; устранил утечку `attestedForms`; синхронизировал доки | честность модели; verify не должен доверять report; тестировать сам аудит |
| **N1** гигиена | стейл-комменты, dead code, единый `WORD_PATTERN`, overlap-guard в Pass 1-4 (defensive — overlap структурно невозможен) | — |
| **N2** пилот курации | 4 реальные `Ἰησοῦς`-пары вскрыли **реальный баг**: build требовал `wordIndexes.length>=2` и падал на одноэлементном массиве — рассинхрон с verify (`>=1`); не ловился, т.к. путь имел 0 записей | **непротестированные пути (0 записей) прячут рассинхрон build↔verify контрактов** |
| **N3** lexicon hardening | corroboration-guard: контестных всего **6 из 6335 (0.09%)** | тир был безопаснее, чем казалось; guard закрывает класс на будущее |

Итог: aligned 58 976 (81.8%), auto-deferred 13 106 (backlog), manual-pair 4, no-bsb 15, no-gloss 5.

## 6. Шпаргалка для других переводов и языков

Переиспользуемые выводы (метод обобщается на любую пару «подстрочник/глоссы ↔ свободный перевод»):

1. **Сначала фундамент текста.** Корректная сборка отображаемого текста + токенизация (offsets) —
   до выравнивания. Баги склейки/токенизации тихо портят span'ы. Версионируй текст и бампай при правках.
2. **Используй обе формы глоссы.** Если есть «богатая» (с предлогами/артиклями) и «чистая» (bare
   lemma) глоссы — чистая матчит одно слово перевода. Это часто крупнейший безопасный резерв покрытия.
3. **Только единственный кандидат.** Никогда не угадывай между неоднозначными повторами — это
   фундамент точности. Лучше отложить, чем дать неверную пару.
4. **Раздели 3 уровня правильности.** Гейть на формальном (slice↔глосса по методу) + полном
   разбиении токенов; НЕ на проценте покрытия. Семантику — человеком, выборочно.
5. **Честный backlog, не фейковая курация.** Не-выровненное классифицируй авто-категорией
   («алгоритм не разрешил»), а не псевдо-«человек исключил». Иначе теряешь и честность, и рабочий
   список для доводки.
6. **Тиринг методов + реестр.** Закрытый перечень методов; per-method инвариант; неизвестный метод
   валит verify. Слабые методы (лемма-уровневые глоссы) — audit-required + corroboration.
7. **Курация через индексы, не офсеты.** Инструмент показывает текст с индексами слов; куратор
   задаёт `wordIndex`+`expectedText`; build компилирует span и сверяет. Сырые офсеты = неизбежные ошибки.
8. **Тестируй сам аудит и пустые пути.** Скрипт аудита, который «аудирует 0», бесполезен. Пути с 0
   записей (ручные пары) прячут рассинхрон build↔verify — прогони пилот на живых данных.
9. **Versification/textual variants.** Стихи источника без стиха перевода → отдельная авто-категория
   исключения (не пытаться выровнять — span'а не существует).
10. **verify не доверяет report.** Hard-gate пересчитывает партицию из реальных токенов и сверяет с
    агрегатами, а не верит числам из отчёта сборки.
