## 0. Почему этот план, а не PHASE-B

PHASE-B (параметризация путей `eng`→`en/bsb`) — **грамотный, но преждевременный**
рефакторинг: по собственному разделу «Что НЕ делается» он не добавляет ни второго
перевода, ни UI выбора — пользователь до и после видит идентичное приложение.
Вся его мотивация — «фундамент для Этапа В», а Этап В (русский Синодальный)
заблокирован лицензией (PROJECT.md §7). Делать абстракцию мульти-перевода,
имея один перевод, — проектирование против гипотезы; к тому же он один раз
платит миграцией PWA-кешей за переименование, а второй раз заплатит ею же при
добавлении реального перевода.

**Решение:** PHASE-B → backlog. Выполнить его как естественную часть добавления
конкретного лицензированного второго перевода (тогда переименование путей не
отдельный риск, а побочный эффект реальной работы). Сейчас — релиз того, что есть.

**Техдолг (сознательный):** жёсткие пути `bibles/eng/`, `bibles/grc/`,
`align/grc-eng/` и строковые константы `'eng'`/`'grc'` в `bible-loader.js` и
`reading.js` остаются в коде. Они не мешают текущему пользователю, но следующий
разработчик, добавляющий перевод, ОБЯЗАН сначала выполнить PHASE-B
(параметризацию), и только потом добавлять данные нового перевода. Попытка
добавить второй перевод без параметризации создаст ещё больше жёстких путей
и кратно усложнит последующую распуть. Триггер погашения долга: появление
конкретного перевода с чистой лицензией (кандидат: русский Синодальный или
другой public domain / CC перевод).

## R2 — Ручной QA: существующий пользователь (v1.0.x → v2)

Самый рискованный путь: у части пользователей в IndexedDB лежат данные старого
приложения (Синодальный, legacy-ключи словаря `slug`/`freq-*`, старые SW-кеши).

**Подготовка стенда:** два уровня проверки миграции:

1. **Юнит-тесты миграции (добавить в `tests/dictionary.test.js`):**
   - Подать словарь с реальными legacy-ключами v1.0.x (`iesous`, `freq-2424`, `freq-976`).
   - Проверить: ключи перенесены в `lexemeId` (`grc-iesoys-2fba61` и т.д.).
   - Проверить: неоднозначный ключ помечен `_legacy:true`, НЕ удалён.
   - Проверить: идемпотентность (повторный вызов не меняет результат).
   - Проверить: `progress.wordsToday.added` — ключи в нём тоже мигрированы.
   - Проверить: `saveMigrationResults` пишет `dictionary_migration_warnings` при конфликтах.
   - Это чистые функции — без IndexedDB/DOM, Vitest.

2. **Ручная проверка в браузере:** если есть доступ к старой сборке v1.0.x — снять
   снимок её IndexedDB. Если нет — открыть актуальную сборку, в DevTools
   (Application → IndexedDB → ru2agr_db → app_state) вставить засев:
- `settings` без полей v2 (проверка merge с DEFAULTS),
- `dictionary` с несколькими legacy-ключами (`slug`-вид и `freq-*`),
- `progress` со старым `reading.lastBook`.

Проверки:
- [ ] **Миграция словаря**: при входе в читалку (`reading.js mount`)
      `migrateDictionaryData` переносит legacy-ключи → `lexemeId` идемпотентно;
      однозначные ключи мигрированы, неоднозначные помечены `_legacy:true` и
      **не удалены** (RUNTIME.md §4). Повторный вход не дублирует/не ломает.
- [ ] **Предупреждения миграции** пишутся в `dictionary_migration_warnings`
      fail-soft (отсутствие стораджа не валит приложение).
- [ ] **Очистка старых кешей**: `cleanupOldDataCaches` (app.js ~88) удаляет
      `book-packs*`/`lexicon-data*` без суффикса `-v2`; `*-v2` сохраняются.
- [ ] **Апдейт SW**: при новой сборке `wb 'activated' (isUpdate)` → авто-reload
      (app.js ~73); пользователь не застревает на старом ассете.
- [ ] **Оффлайн после апдейта**: выключить сеть → чтение уже открытой книги
      работает (book-pack в кеше), приложение не «белый экран».
- [ ] Старый `settings` без `theme`/новых полей → merge с DEFAULTS, без ошибок.

**Гейт R2:** словарь пользователя переживает миграцию без потери данных; апдейт
SW не оставляет смешанных старых/новых ассетов. Потеря пользовательских данных —
жёсткий блокер.

## После этапа

Релиз закрыт → следующий приоритет выбирает владелец из PROJECT.md §7:
курация backlog `auto-deferred` (повышение coverage без потери точности) **или**
PHASE-B+Этап В (когда появится лицензированный второй перевод). Эти треки
независимы; данный этап ни один из них не предрешает.
