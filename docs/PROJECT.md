## 1. Что это

«Греческая читалка Нового Завета» — PWA для изучения греческого НЗ через чтение. Пользователь
читает английский текст BSB, а поверх него постепенно проступает греческий слой: буквы, затем
слова (леммы или реальные формы), с карточками лемм и личным словарём. UI — русский.

**Зачем миграция (v2).** Старый пайплайн опирался на UBS-данные с лицензией «used with permission
only for MACULA» — неприемлемо. v2 переехал на источники с чистыми лицензиями:
- **BSB** (Berean Standard Bible) — английский текст, public domain.
- **SBLGNT / MACULA** — греческий текст + морфология, CC BY 4.0.
- **Berean glosses** (PD) + **Cherith glosses** (CC BY 4.0) — пословные глоссы к каждому токену.

Греко-английское **выравнивание строится алгоритмически при сборке** (span-based: глосса → слово
BSB). Невыровненное не рендерится как греческая вставка (деградация, не баг).

## 4. Модель данных (обзор)

Источник (`docs/source-data/`) → сборка → app-ready (`assets/data/`). Паки и их версии «сшиты»
двумя идентификаторами снимка (`sourceDataVersion`, `normalizationVersion`), которые verify сверяет
между паками. Контракты схем и провенанс версий — в [PIPELINE.md](PIPELINE.md §schemas).

```
assets/data/
├── bibles/grc/{book}.json        грек: токены + морфология + глоссы (schema original-book-v2)
├── bibles/eng/{book}.json        BSB: text + words[] (UTF-16 offsets) (translation-book-v2)
├── align/grc-eng/{book}.json     пары + exclusionsByRef (alignment-book-v3)
├── align/grc-eng/build-report.json   метрики + topUnalignedLexemes (backlog)
├── lexicon/core.json             5468 лемм (+ detail из Strong's)
├── lexicon/dictionary.json       Strong's + рус. соответствия (5624 записи)
├── alphabet.json, books.json, data-manifest.json
```

## 5. Политика гейта выравнивания (решение продукта)

**Точность важнее покрытия.** Hard-gate релиза — НЕ процент покрытия, а две машинные проверки:
1. **Accuracy-инвариант**: каждая пара формально соответствует глоссе по своему методу; `q`
   соответствует методу; proposal-тир запрещён в релизных данных.
2. **Полное разбиение**: каждый `fw=false` токен ровно в одной категории (aligned XOR одна
   resolution-kind). Нет неклассифицированных.

Coverage% — **advisory** (никогда не блокирует релиз). Защита от «слишком многое отложили» — не
процент, а явная причина у каждой категории + аудит. Полная модель, тиринг методов и инварианты —
в [ALIGNMENT.md](ALIGNMENT.md).

## 7. Идеи на будущее

**Выравнивание (повысить покрытие, не теряя точность):**
- Курация backlog'а `auto-deferred` (13 106): топ-леммы `topUnalignedLexemes` (λέγω 427, εἰμί 418,
  πᾶς 225, θεός 217, Ἰησοῦς, κύριος…). Через `curate-align.mjs` → `manual-alignments.json`
  (wordIndex/expectedText). Каждая пара поднимает coverage на 1 токен, точность не страдает.
- SOV/SVO и subset-фразы: phrase-проход v1 берёт только contiguous-окно того же порядка. Перестановки
  и частичные совпадения — отдельная итерация (риск точности → за флагом/proposal-тиром).
- Conflict-aware matching вместо greedy (собрать все кандидаты, принять бесконфликтные) — для
  устранения латентного риска порядка проходов.

**Продукт:**
- Возврат русского перевода отдельным лицензионным этапом (сейчас source-текст английский).
- **Локализация UI английский/русский** — спроектирована, план готов,
  реализация после Phase B. См. [LOCALIZATION.md](LOCALIZATION.md).
- Закрыть открытые рантайм-issue (§8) перед релизом.

**Переиспользование (другие переводы/языки):** метод выравнивания обобщаем на любую пару
«подстрочник ↔ свободный перевод». Шпаргалка с выводами — в [ALIGNMENT.md §lessons](ALIGNMENT.md).
