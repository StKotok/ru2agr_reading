> Этап после Phase B. Проектирует модуль `src/i18n/`, схему URL, интеграцию
> с роутером/настройками/store, data-driven строки (книги, глоссы) и план
> миграции ~200 зашитых строк в 15+ файлах.

## 1. Что и зачем

**Цель:** пользователь выбирает язык интерфейса (русский / английский). Язык
сохраняется в настройках, отражается в URL, авто-детектится при первом заходе.
Всё, что пользователь видит кроме текста Писания и греческих токенов, меняет
язык.

**Полный охват:**
- UI-хром (навигация, заголовки, кнопки, aria-label)
- Названия книг (books.json)
- Словарные глоссы (core.json / dictionary.json — выбор поля по языку)
- Контент чтения (data-notice, хинты, онбординг, подписи)

**Что НЕ меняется:**
- Текст BSB (всегда английский)
- Греческий текст SBLGNT (всегда греческий)
- Буквенный слой, режимы чтения, выравнивание
- Структура IndexedDB (store/settings/progress/dictionary)
- Схемы данных (original-book-v2, translation-book-v2, alignment-book-v3)
- PWA-кеши (cacheName не трогаем — Phase B их меняет)

## 2. Архитектура модуля `src/i18n/`

```
src/i18n/
├── index.js      # I18n-класс + singleton export
├── ru.json       # Русский словарь переводов
└── en.json       # Английский словарь переводов
```

### 2.1. API класса `I18n`

```js
// src/i18n/index.js

class I18n {
  constructor()
  // Инициализация: загружает переводы, детектит язык, подписывается на store.
  // Вызвать ОДИН раз при старте приложения (app.js), до монтирования экранов.
  async init(store, settings) → void

  // Основной метод: ключ → перевод. Поддерживает {{var}} интерполяцию
  // и плюрализацию через Intl.PluralRules.
  t(key, params?) → string
  // Примеры:
  //   i18n.t('nav.reading')                     → 'Чтение' / 'Reading'
  //   i18n.t('reading.chapter', { n: 5 })       → 'глава 5' / 'chapter 5'
  //   i18n.t('dict.wordsCount', { count: 5 })   → '5 слов' / '5 words'

  // Текущий язык.
  get lang() → 'ru' | 'en'

  // Смена языка: загружает переводы если нужно, персистит в settings,
  // обновляет URL. Возвращает промис (дождаться загрузки переводов).
  async setLang(lang) → void

  // Авто-детект из браузера: navigator.language → 'ru' | 'en'.
  // 'ru' для ru/uk/be/kk; всё остальное → 'en'.
  detectBrowserLang() → 'ru' | 'en'

  // Извлечь язык из URL-префикса ('#/ru/read/john' → 'ru').
  // Возвращает null если префикса нет (старый формат URL).
  langFromPath(path) → 'ru' | 'en' | null

  // Сгенерировать URL-префикс для текущего языка.
  langPrefix(lang?) → `/${lang}`  // напр. '/ru'

  // Data-driven хелперы:

  // Название книги на текущем языке.
  bookName(book) → { short, title }
  // book.short → берёт short или shortEn по lang

  // Глосса леммы на текущем языке.
  gloss(lexeme) → string | null
  // ru → lexeme.ruGloss, en → glossesBerean[0]

  // Метка темы на текущем языке.
  themeLabel(slug) → string
  // pergament → 'Пергамент' / 'Parchment'

  // Метка контраста на текущем языке.
  contrastLabel(level) → string
  // sharp → 'Чёткий' / 'Sharp'

  // Закрытие: отписка от store.
  destroy() → void
}

// Singleton — один экземпляр на всё приложение.
export const i18n = new I18n();
```

### 2.2. Плюрализация

Использует `Intl.PluralRules` — встроенный API браузера, без зависимостей.

```json
// ru.json — русская плюрализация (one / few / many)
"dict.wordsCount": {
  "one":  "{{count}} слово",
  "few":  "{{count}} слова",
  "many": "{{count}} слов"
}

// en.json — английская (one / other)
"dict.wordsCount": {
  "one":   "{{count}} word",
  "other": "{{count}} words"
}
```

Логика в `t()`:
1. Ищет ключ в словаре. Если значение — строка → возвращает с интерполяцией.
2. Если значение — объект с ключами `one`/`few`/`many`/`other` → выбирает
   по `Intl.PluralRules(lang).select(count)` и интерполирует `{{count}}`.
3. Если ключ не найден → возвращает сам ключ (fail-visible) + console.warn.

### 2.3. Загрузка переводов

```js
async _loadTranslations(lang) {
  if (this._translations[lang]) return; // уже загружено
  const mod = await import(`./${lang}.json`);
  this._translations[lang] = mod.default || mod;
}
```

Динамический import — не грузим оба языка сразу. При первом заходе грузится
только один. При переключении — второй подгружается лениво.

### 3.2. Интерполяция в переводах

Шаблон `{{var}}` заменяется на значение из `params`:
```js
t('reading.heading', { title: 'Иоанн' })
// 'Чтение — Иоанн' / 'Reading — John'
```

Переменная `{{count}}` зарезервирована для плюрализации. Если ключ-строка
содержит `{{count}}` и в params передан `count`, используется плюрализация
автоматически.

## 4. Интеграция с роутером

### 4.1. Новая схема URL

```
Было:                       Стало:
#/read/john                 #/ru/read/john
#/dictionary                #/ru/dictionary
#/settings                  #/ru/settings
#/progress                  #/ru/progress
#/onboarding                #/ru/onboarding
#/about                     #/ru/about
```

### 4.2. Изменения в `src/router.js`

```js
const ROUTES = [
  { pattern: /^#\/(ru|en)\/read\/([a-z0-9]+)$/, screen: 'reading', paramNames: ['lang', 'book'] },
  { pattern: /^#\/(ru|en)\/dictionary$/,        screen: 'dictionary', paramNames: ['lang'] },
  { pattern: /^#\/(ru|en)\/progress$/,          screen: 'progress', paramNames: ['lang'] },
  { pattern: /^#\/(ru|en)\/settings$/,          screen: 'settings', paramNames: ['lang'] },
  { pattern: /^#\/(ru|en)\/onboarding$/,        screen: 'onboarding', paramNames: ['lang'] },
  { pattern: /^#\/(ru|en)\/about$/,             screen: 'about', paramNames: ['lang'] },
];

export function parse(hash) {
  const h = hash || location.hash || '';
  for (const route of ROUTES) {
    const match = h.match(route.pattern);
    if (match) {
      const params = {};
      route.paramNames.forEach((name, i) => { params[name] = match[i + 1]; });
      return { screen: route.screen, params };
    }
  }
  // Дефолт: русский + чтение Иоанна
  return { screen: 'reading', params: { lang: 'ru', book: 'john' } };
}

// navigate принимает путь БЕЗ языкового префикса — префикс добавляется
// из текущего языка автоматически.
export function navigate(path) {
  const lang = i18n.lang;
  location.hash = `#/${lang}${path}`; // path = '/read/john', '/dictionary', ...
}
```

### 4.3. Обратная совместимость со старыми URL

При загрузке старого URL без языкового префикса (`#/read/john`):
1. `parse()` не матчит новые паттерны → возвращает дефолт `{ lang: 'ru', ... }`
2. `app.js` вызывает `i18n.init()`, тот детектит язык
3. Редирект: `location.hash = '#/{detected}/read/john'`

Реализация — в `app.js`, не в роутере:
```js
// В handleRoute:
if (!route.params.lang) {
  const detected = i18n.lang; // уже проинициализирован
  location.replace(`#/${detected}/${route.screen}/${route.params.book || ''}`);
  return;
}
```

## 5. Интеграция с настройками

### 5.1. Новое поле в `settings.js`

```js
const DEFAULTS = {
  // ... существующие поля ...
  uiLang: null,  // null = не выбран (авто-детект при первом запуске)
};
```

`null` означает «язык ещё не выбран» — триггерит авто-детект в `i18n.init()`.
После первого детекта значение становится `'ru'` или `'en'` и сохраняется
в IndexedDB.

```js
    btn.textContent = opt.label;
    btn.addEventListener('click', async () => {
      await i18n.setLang(opt.value);
      settings = { ...settings, uiLang: opt.value };
      saveSettings(settings);
      store.update(s => ({ ...s, settings }));
      render(); // перерендер всей страницы настроек
    });
    bar.appendChild(btn);
  });
  container.appendChild(bar);
}
```

## 6. Data-driven строки

### 6.1. Названия книг (`books.json`)

Источник: `docs/source-data/app-config/books.json` → копируется как есть
в `assets/data/books.json` скриптом `build-app-config.mjs`.

**Решение: добавить параллельные поля** `shortEn` и `titleEn` в source-файл.
Скрипт сборки менять не нужно — он копирует JSON как есть.

```json
[
  { "id": "john", "short": "Ин", "title": "От Иоанна святое благовествование",
    "shortEn": "Jn", "titleEn": "John", "chapters": 21, "order": 4 },
  { "id": "matthew", "short": "Мф", "title": "От Матфея святое благовествование",
    "shortEn": "Mt", "titleEn": "Matthew", "chapters": 28, "order": 1 }
]
```

Почему не вложенный объект `name: { ru: {...}, en: {...} }`:
- Только 2 языка — вложенность избыточна
- Параллельные поля — минимальный дифф в consumers
- При добавлении 3-го языка мигрировать на вложенную схему тривиально

**Хелпер `i18n.bookName(book)`:**
```js
bookName(book) {
  const suffix = this._lang === 'en' ? 'En' : '';
  return {
    short: book[`short${suffix}`] || book.short,
    title: book[`title${suffix}`] || book.title
  };
}
```

**Consumers (5 мест):**
- `reading.js`: `updateBookLabel()`, `renderBookList()`, chapter heading
- `dictionary.js`: не трогает книги
- `progress.js`: `renderReadingSection()`
- `top-bar.js`: `updateBookLabel()`, `renderBookList()`

Везде заменить `book.short` → `i18n.bookName(book).short`,
`book.title` → `i18n.bookName(book).title`.

### 6.2. Словарные глоссы

`core.json` уже содержит данные для обоих языков:
- `ruGloss` — русский глосс (сейчас используется везде)
- `glossesBerean` / `glossesCherith` — английские глоссы

**Хелпер `i18n.gloss(lexeme)`:**
```js
gloss(lexeme) {
  if (!lexeme) return null;
  if (this._lang === 'ru') return lexeme.ruGloss || null;
  // Английский: предпочитаем Berean, fallback Cherith
  return lexeme.glossesBerean?.[0] || lexeme.ruGloss || null;
}
```

`ruGloss` как fallback для английского сознателен — глоссы Berean/Cherith
есть не у всех лемм, но лучше показать русский глосс чем ничего.

**Consumers:**
- `dictionary.js`: `buildWordCard()` — поле `ruGloss`
- `word-card.js`: `renderWordCard()` — поле `gloss`

### 6.3. Темы и контраст

**Удалить `THEME_LABELS` и `CONTRAST_LABELS` из `settings.js`** —
они переезжают в переводы (`theme.*` и `contrast.*`).

**Хелперы:**
```js
themeLabel(slug) { return this.t(`theme.${slug}`); }
contrastLabel(level) { return this.t(`contrast.${level}`); }
```

**Consumers:**
- `settings.js` (screen): `themeLabel()`, `contrastLabel()`
- `nav.js`: theme switcher labels (уже в `nav.*` ключах)

## 7. Интеграция со store

### 7.1. Инициализация в `app.js`

```js
import { i18n } from './i18n/index.js';

// ... после загрузки settings, до монтирования экранов:
const settings = await loadSettings();
await i18n.init(store, settings);

// После инициализации — синхронизация URL если нужно
// (редирект старого формата URL)
```

### 7.2. Реактивность

`i18n.init()` подписывается на `store.subscribe(['settings'])`:
- Если `uiLang` изменился → `setLang()` → перезагружает переводы
- Не вызывает `store.update()` сам — только читает

Изменение языка НЕ вызывает автоматический перерендер всех экранов.
Каждый экран перерендеривается через существующий механизм:
- `switchScreen()` в `app.js` пересоздаёт экран целиком (unmount → mount)
- Навигация на ту же страницу с новым языком → `location.hash` меняется →
  `handleRoute` → `switchScreen` → полный перерендер

Для мгновенного переключения без перезагрузки страницы: в `i18n.setLang()`
после смены языка вызывается `navigate()` на тот же экран — триггерит
`hashchange` → `switchScreen`.

### 7.3. Поток при старте приложения

```
1. app.js: loadSettings()
2. app.js: applyTheme(), applyContrast()
3. app.js: i18n.init(store, settings)
   ├── i18n: _lang = settings.uiLang || detectBrowserLang()
   ├── i18n: _loadTranslations(_lang)
   ├── i18n: subscribe to store.settings
   └── i18n: if settings.uiLang === null → save uiLang to settings
4. app.js: handleRoute(parse(location.hash))
   ├── if route.params.lang is null → redirect to #/detected/...
   └── else → switchScreen(route.screen, route.params)
5. Все экраны используют i18n.t() при mount → получают правильный язык
```

## 11. Риски

| Риск | Смягчение |
|---|---|
| Динамический `import()` для JSON — не все bundler'ы поддерживают | Vite поддерживает JSON-импорты из коробки (`vite.config.js` уже не меняем) |
| Старые URL без префикса ломают навигацию | Обратная совместимость в `handleRoute`: редирект с авто-детектом |
| IndexedDB-настройки без `uiLang` у существующих пользователей | `null` = авто-детект, идемпотентно |
| `books.json` генерируется из source-файла — нужно добавить En-поля в источник | `docs/source-data/app-config/books.json` → добавить `shortEn`/`titleEn`; сборка копирует как есть |
| Переключение языка не обновляет текст на лету (только через ремонтирование экрана) | `navigate()` с тем же экраном → unmount/mount → новый `i18n.t()` |
