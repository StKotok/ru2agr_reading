# Выбор светлой и тёмной темы независимо — топ-5 идей

**Контекст**: в текущем прототипе (`ru2gr.dc.html`, `canvas-header`) все 12 тем
(9 светлых + 3 тёмных) свалены в один `<select>`. Пользователь не может отдельно
назначить «любимую светлую» и «любимую тёмную» — и нет авто-переключения по системе.

**Задача**: дать читателю возможность независимо выбрать светлую и тёмную тему, с
автоматическим переключением по системному dark mode (или вручную).

**Дизайн-контекст**: приложение для длительного чтения. Комфорт глаз — главный
приоритет. Аудитория — читатели Нового Завета на греческом, не обязательно
технически продвинутые.

---

## Идея 1: Системный авто-режим + парные карточки тем (Рекомендуемая)

### Суть
Сегментный переключатель режима:
`[🌓 Система] [☀️ Светлая] [🌙 Тёмная]`

Под ним — два ряда **карточек-превью** тем: «Светлые» и «Тёмные». Каждая карточка —
миниатюра 72×48px с реальными цветами: бумага, текст, акцент. При клике —
мгновенное применение ко всему интерфейсу.

В режиме «Система» активны оба ряда. В режиме «Светлая» — только светлый ряд
(тёмный скрыт). В режиме «Тёмная» — наоборот.

### Почему это работает
- **Ментальная модель**: «я выбираю пару: светлую тему и тёмную»
- **Визуальное превью** снижает когнитивную нагрузку — не надо помнить названия
- **Системный режим** = zero-interaction для 80% пользователей
- **Быстрый A/B**: один тап по карточке — и тема применена, сравнивай сразу

### Макет (ASCII)
```
┌─────────────────────────────────────────────────┐
│  Режим:  [🌓 Система]  [☀️ Светлая]  [🌙 Тёмная] │
│                                                 │
│  Светлые темы                                   │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │Перга- │ │Сепия │ │Слон. │ │Туман │ │ Море │  │
│  │мент ✓│ │      │ │кость │ │      │ │      │  │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘  │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐           │
│  │ Лес  │ │ Роза │ │Лаван-│ │Закат │           │
│  │      │ │      │ │  да  │ │      │           │
│  └──────┘ └──────┘ └──────┘ └──────┘           │
│                                                 │
│  Тёмные темы                                    │
│  ┌──────┐ ┌──────┐ ┌──────┐                    │
│  │Тёмная│ │ Ночь │ │Уголь │                    │
│  │      │ │  ✓   │ │      │                    │
│  └──────┘ └──────┘ └──────┘                    │
└─────────────────────────────────────────────────┘
```

### Плюсы
- Понятно без инструкции
- Превью тем видно сразу, не надо скроллить `<select>`
- Один тап = применение (нет лишнего «Применить»)
- Хорошо скейлится на мобильных (сетка 3–4 в ряд)
- Соответствует современным паттернам (iOS Settings, VS Code)

### Минусы
- Требует места: ~180–200px по вертикали
- Нужно рисовать превью для каждой темы
- На очень узких экранах (≤320px) может потребоваться скролл

## Идея 2: Двойной дропдаун с живым превью

### Суть
Два компактных селекта:
- **Светлая тема** (солнце ☀️): выпадающий список из 9 светлых тем
- **Тёмная тема** (луна 🌙): выпадающий список из 3 тёмных тем

Над ними — переключатель режима: `Авто / Светлая всегда / Тёмная всегда`.

Под селектами — **живой блок превью**: небольшой фрагмент текста (2–3 стиха),
который мгновенно меняется при смене темы в селекте.

### Плюсы
- Компактно (≈120px высоты)
- Почти не ломает текущий UI
- Живое превью = доверие к выбору
- Привычный паттерн для возрастной аудитории

### Минусы
- Дропдаун требует двух кликов (открыть → выбрать)
- Не видно все темы сразу — нужно открывать по одной
- Превью-блок может быть проигнорирован
- Нет визуального сравнения тем «глазами»

## Идея 3: «Семейства тем» — светлая + тёмная в паре

### Суть
Вместо независимого выбора — **9 предустановленных пар** (семейств). Каждая пара
объединяет одну светлую и одну тёмную тему, стилистически согласованные.

Отображение: горизонтальный скролл карточек-пар. Каждая карточка показывает
два цветовых образца рядом (слева светлый, справа тёмный).

### Плюсы
- Самый быстрый путь к выбору (1 тап)
- Дизайнерский контроль над сочетаниями
- Нет «паралича выбора» (choice overload)

### Минусы
- Ограничивает свободу: нельзя выбрать «Пергамент + Ночь» если такой пары нет
- Требует дизайн-решения: какие пары предложить?

## Идея 4: Визуальная сетка тем с drag-to-pair

### Суть
Все 12 тем отображаются в виде **плиток-свотчей** в две строки.
Пользователь **тапает одну светлую и одну тёмную** — они подсвечиваются
как «активная пара».

### Плюсы
- Очень наглядно — сразу видно все 12 тем
- Приятный интерактив («собираю свою тему»)
- Хорошо работает и на мобильном, и на десктопе

### Минусы
- 12 свотчей требуют места (~220px по вертикали)
- Может быть непонятно для нетехнических пользователей

## Идея 5: «Время суток» — три слота с авто-переключением по расписанию

### Суть
Вместо технического «light/dark» — **человеческая метафора времени суток**.
Три слота, каждый со своей темой и временем активации:

| Слот | Время по умолчанию | Какие темы |
|------|-------------------|------------|
| ☀️ **Утро/День** | 06:00 – 17:00 | 9 светлых |
| 🌅 **Вечер** | 17:00 – 22:00 | Сепия, Закат, Роза, Тёмная (приглушённые) |
| 🌙 **Ночь** | 22:00 – 06:00 | 3 тёмных |

### Плюсы
- Самая «тёплая» и человеко-ориентированная модель
- Три слота вместо двух = более точный комфорт в течение дня
- Хорошо для приложения-читалки: многие читают в разное время суток
- Дифференцирует продукт (мало кто делает 3-слотовую модель)

### Минусы
- Самый сложный в реализации
- Настройка времени — дополнительный UI
- Может быть избыточным для пользователей, которые всегда предпочитают один режим

## Рекомендация

Для **первой итерации** — **Идея 1 (Системный авто-режим + карточки)**.
Причины:
1. Баланс «простота / гибкость» — пользователь видит всё и выбирает за 1 тап
2. Системное авто-переключение покрывает 80% сценариев
3. Хорошо скейлится с мобильного на десктоп
4. Соответствует современным паттернам (iOS 17+, VS Code, Telegram)
5. Легко добавить «продвинутый режим» → Идея 2 (дропдауны) для тех,
   кому нужно больше контроля

Для **будущей итерации** — **Идея 5 (Время суток)** как дифференциатор
для приложения-читалки. Три слота с авто-переключением по времени —
это именно то, что оценят читатели, которые открывают приложение
и утром за кофе, и вечером перед сном.

## Принципы, использованные из UI/UX Pro Max

| Принцип | Где применён |
|---------|-------------|
| `dark-mode-pairing` (§4) | Все идеи строятся вокруг пар «светлая + тёмная» |
| `touch-target-size` (§2) | Карточки-превью ≥ 44×44px, даже самые маленькие |
| `color-dark-mode` (§6) | Тёмные темы используют приглушённые цвета, не инвертированные |
| `token-driven-theming` (§6) | Все темы — семантические токены (`THEMES`), не хардкод |
| `state-clarity` (§4) | Выбранная тема всегда визуально отмечена (checkmark, обводка) |
| `primary-action` (§4) | Один primary CTA на экран настроек — «выбор темы» |
| `progressive-disclosure` (§8) | Базовый выбор темы → продвинутые настройки времени (Идея 5) |
| `consistency` (§4) | Один визуальный язык свотчей/карточек для всех тем |
| `system-controls` (§4) | Предпочтение нативных `<select>`/радиокнопок где возможно |
